What is ZeroShare?

ZeroShare is a browser-based peer-to-peer file transfer application designed for private and encrypted file sharing between devices.

Instead of following a conventional upload-and-download workflow, ZeroShare uses WebRTC to establish communication between participating browsers. File data is encrypted locally before the application-level payload is transmitted.

Privacy by Design

Client-Side Encryption

File data is encrypted in the browser before it is sent through the WebRTC data channel.

Peer-to-Peer Transfer

ZeroShare is designed around browser-to-browser transfer rather than conventional centralized file storage.

ECDH Key Agreement

Participating browsers use ECDH key agreement to derive shared cryptographic key material.

AES-256-GCM

Authenticated encryption protects file chunks before they enter the WebRTC transport.

How ZeroShare Works

1

Establish a peer connection

The participating browsers use signaling and WebRTC ICE negotiation to discover a usable network path.

2

Derive shared key material

Public key material is exchanged and ECDH is used to derive the shared key required by the transfer protocol.

3

Encrypt the file locally

File data is processed in chunks and encrypted with AES-256-GCM inside the browser.

4

Transfer and decrypt locally

Encrypted chunks are transferred through the WebRTC data channel and decrypted by the receiving browser.

Security Architecture

Web Crypto API

Browser-native cryptographic APIs perform encryption and key operations locally.

AES-256-GCM

Provides authenticated encryption for application-level file data.

WebRTC Data Channels

Provides the browser-to-browser transport used for transferring encrypted file data.

STUN and TURN

Network traversal infrastructure can assist WebRTC when a direct peer connection is unavailable.

Understanding the Network

Peer-to-peer does not mean that every WebRTC connection can always be established directly. NAT, firewalls and network policies can prevent a direct route between browsers.

When necessary, WebRTC can use TURN infrastructure to relay encrypted transport traffic. This is different from uploading the original file to a conventional file-storage service.

Signaling and network infrastructure can still process connection-related metadata required to establish and maintain a WebRTC connection.

Frequently Asked Questions

What is ZeroShare?

ZeroShare is a browser-based peer-to-peer file transfer application designed for private and encrypted file sharing between devices.

How does ZeroShare protect file contents?

ZeroShare encrypts file data in the browser using AES-256-GCM before encrypted chunks are transmitted through the WebRTC data channel.

Does ZeroShare upload my original file?

ZeroShare is designed around peer-to-peer transfer rather than conventional server-side file storage. WebRTC signaling and network traversal infrastructure may still participate in establishing a connection.

Can ZeroShare transfer large files?

ZeroShare supports large file transfers, subject to browser memory, device resources, network conditions and the capabilities of the participating devices.

Does ZeroShare require an account?

The core file-sharing workflow is designed around browser peers rather than a traditional account-based cloud-storage workflow.
